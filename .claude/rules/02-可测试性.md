# 规则：可测试性 —— 纯函数 + 组件拆分

> owner：测试层不变量。来源：PRD §2 技术栈（Vitest 只测纯函数）、§5 测试、§8 实现提示。

## 规则

1. 每个工具的转换/校验/编解码逻辑**必须**拆为纯函数，放进该工具的 `utils` 目录（如 `src/tools/json/utils.ts`）；组件只做 UI 编排。
2. 纯函数要求：无副作用、无 DOM/React 依赖、可被 `vitest` 直接 import。允许使用浏览器全局纯 API（`TextEncoder`、`JSON`、`crypto` 在函数内传入注入）。
3. **Vitest 只测纯函数**，不测组件渲染、不做 E2E（PRD §6 明确不做 E2E）。组件行为通过纯函数覆盖间接保证。
4. 必测覆盖（PRD §5 列出的 5 组）：
   - 时间戳互转（ts→time、time→ts，s/ms，非法输入）
   - Base64 编解码（**UTF-8 中文必须正确**，URL-safe 模式）
   - URL 编解码（`encodeURIComponent`/`decodeURIComponent` 与 `encodeURI`/`decodeURI`，解码失败）
   - UUID v4 格式校验（大写/去横线/花括号选项）
   - JSON 校验（非法时行号+列号+错误信息）与按键名递归排序
5. 每个工具至少覆盖：合法输入、非法输入、边界（空串/上限）三类用例，不能只测 happy path。
6. 新增工具或修改 utils 后，必须运行 `npx vitest run` 全量通过才能提交。

## 判例标准

- 在组件文件内写转换逻辑（如 `onClick` 里直接拼 Base64）= 违规，抽到 utils。
- utils 函数签名带 React 类型（Component、Context）= 违规。
- 测试断言只验证 "不抛异常" 而不验证输出值 = 不通过。
